# MVP Requirements

**Document ID:** PROD-001  
**Version:** 0.1  
**Status:** Draft  
**Depends on:** PRD.md

## 1. Purpose
Define the first usable release of Expense Analyzer: a secure India-focused personal-finance analysis product that turns uploaded statements into trustworthy transactions, analytics, and actionable insights.

## 2. MVP User
Primary user: an Indian individual managing personal finances across bank accounts, credit/debit cards, UPI, cash, subscriptions, EMIs, insurance, rent, utilities, and investments.

## 3. Functional Requirements

### FR-01 Authentication
- Users can register, log in, log out, and retrieve their profile.
- Authentication credentials are never exposed in logs.
- Every protected resource is authorized against the authenticated user.

### FR-02 Account Management
- Users can create, view, update, and delete financial accounts.
- Account types support bank, credit card, debit card, cash, and other extensible types.
- Account ownership is mandatory.

### FR-03 Statement Upload
- Upload CSV and supported text/structured PDF statements.
- Validate file type, size, content, and basic safety constraints.
- Store the original file in object storage.
- Compute a checksum for deduplication.
- Return a statement ID and processing status.

### FR-04 Asynchronous Processing
- Upload initiation must not wait for full document processing.
- Processing states: UPLOADED, QUEUED, PROCESSING, COMPLETED, FAILED.
- Failures retain a safe, user-readable error.
- Jobs/events are retryable and idempotent.

### FR-05 Transaction Extraction
- Extract transaction date, posting date where available, amount, currency, direction, and raw description.
- Preserve recoverable source information.
- Validate required fields before persistence.
- Reject or quarantine malformed rows rather than silently inventing values.

### FR-06 Normalization
- Normalize descriptions and merchant names using deterministic rules initially.
- Preserve raw descriptions.
- Store merchant/category confidence where classification is uncertain.

### FR-07 Categorization
Initial system categories:
Food, Transport, Housing, Utilities, Shopping, Entertainment, Subscriptions, Healthcare, Insurance, Education, Travel, Investment, Transfer, Income, Other.
- Categorization is deterministic/rule-based initially.
- Users can review or correct classifications through the transaction model/API.

### FR-08 Duplicate Detection
- Identical statement uploads are detected by checksum.
- Transaction fingerprints help prevent duplicate transaction ingestion.
- Duplicate handling must be deterministic and observable.

### FR-09 Recurring Expenses
- Detect likely recurring expenses from repeated merchant/category and amount/date patterns.
- Store frequency, expected amount, confidence, last occurrence, and next expected date where inferable.
- Results are labeled as predictions, not guarantees.

### FR-10 Anomaly Detection
- Surface unusual transactions or spending changes using explainable deterministic rules in MVP.
- Each anomaly must include evidence sufficient for user review.

### FR-11 Analytics
Provide deterministic:
- spending summary
- category spending
- merchant spending
- period/monthly trends
- cash-flow summary
- recurring expenses
- basic anomalies
- transaction counts and filtered transaction lists
- comparisons between periods

### FR-12 Insights
- Generate explainable insights from verified analytics.
- Insights must reference their period and evidence.
- Financial totals and percentages are calculated by backend code, not generated by an LLM.

### FR-13 Dashboard
- Show a spending summary, major categories/merchants, trends, recurring expenses, anomalies, and notable insights.
- Allow drill-down from aggregate → merchant/category → transaction.

### FR-14 Search and Filtering
Support filters for account, date range, category, merchant, direction, and amount range.

## 4. PDF Scope
MVP targets text-based/structured PDFs. OCR for scanned statements is deferred unless implementation complexity remains acceptable without destabilizing the MVP.

## 5. AI Scope
Core MVP must work without an LLM.
If conversational AI is enabled in MVP+, it must use controlled backend tools and verified analytics. The LLM cannot query the database arbitrarily or be the source of financial truth.

## 6. Non-Functional Requirements
- Secure multi-user isolation.
- TLS in transit and encryption at rest where applicable.
- Structured logging without sensitive financial payloads.
- Rate limiting and upload/resource limits.
- Deterministic financial calculations.
- Idempotent processing.
- Test coverage for domain logic and critical integration paths.
- API and processing failures are observable.

## 7. MVP Acceptance Criteria
1. Scope is documented and agreed.
2. Non-goals are explicit.
3. Primary journeys are documented.
4. Success metrics are measurable.
5. A user can upload a supported CSV statement and retrieve processed transactions.
6. Processing is asynchronous.
7. Transactions can be categorized and queried.
8. Analytics and insights are derived from deterministic backend data.
9. Duplicate uploads do not silently duplicate financial data.
10. One user cannot access another user's financial data.
11. AI and bank integrations are not hidden dependencies.
