## New findings from the E2E run

| Finding | Severity | Suggested fix |
|---|---|---|
| Reloading the page while a token refresh is in flight logs the user out: the server rotates the token, the aborted response never sets the new cookie, and the old one is then rejected as reused | Medium | Give rotated refresh tokens a short grace period (for example 30 s), or accept the previous token once |
| A password login revokes the user's other sessions (E2E needed separate users for this) | Info | Confirm it's intended. It means logging in on a phone signs the user out on the web |
| Concurrent imports race to create the same merchant; one hits a unique-key violation and retries (logged as WARN) | Low | Works as designed. Consider `INSERT … ON CONFLICT DO NOTHING` to remove the log noise |
